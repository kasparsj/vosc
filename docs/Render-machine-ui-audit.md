# Render-machine UI audit

2026-11-22 · Revision `7a4d11a` and working-tree changes present at review. [Design contract](../DESIGN.md) · [View specification](Render-machine-ui.md)

## Verdict

The four-destination dock is a workable structure. Keep it small and put navigation depth inside the active destination. The original clickable study validated the visual direction and one sample diagnostic path with simulated clipboard feedback. Use the inventory below as the brief for later milestones. [Current design in Figma](https://www.figma.com/design/1dWhdS4r5BQkPGDMGvX867?node-id=5-117) · [Historical density review](mockups/render-machine-overlay-density-review/verification.md)

## Findings

| Priority | Finding grounded in the current code | Requirement for the redesign |
| --- | --- | --- |
| High | **Opening the Inspector can interrupt a trial.** Key events and mouse press/release call the trial interruption and epoch bookkeeping before renderer dispatch. The renderer also assigns numbers to layer selection or blend modes depending on debug state, and `r`, `u`, and `w` affect the scene. [Input entry points](../src/VOSC.cpp) · [Renderer dispatch](../src/systems/RenderSystem.cpp) | Model focus ownership from output through the dock, text fields, and nested controls. Navigation, browsing, copying, and returning to output must be observational. Verify that a passive gesture leaves the trial receipt and the configuration epoch unchanged in an isolated run. Keep explicit scene changes distinguishable. |
| High | **A layer index or a cached pointer can outlive the resource it described.** Inspector selects numeric positions without checking that they exist before later access. Shader and texture detail cache raw pointers. Layer reset and replacement can change the live objects at those positions. [Selection](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/Inspector.cpp) · [Layer access](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/Inspector.cpp) · [Cached texture](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/TextureInspector.cpp) · [Cached shader](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/ShaderInspector.cpp) · [Scene reset](../src/systems/CommandSystem.cpp) | Show a changed or unavailable state and recover to an existing parent. Preserve path and focus on ordinary Back. Revalidate the resource before applying texture changes or copying an asset command. A reused layer index requires fresh selection after replacement. |
| High | **The two texture flags are real mutations with different lifetimes.** The current UI writes both booleans directly. A static texture skips updates unless a request is pending and an eligible update clears that request. An owning texture can be shared by several consumers. [Flag writes](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/TextureInspector.cpp) · [Update semantics](../src/Texture.cpp) · [Shared texture selection](Texture-commands.md#overview) | Keep the ability to set and clear both flags. Show persistent static state, pending update, and the owning resource or shared scope. Prefer an explicit **Request update** and **Cancel pending update** pair for the transient flag. The UI shows the resulting live state and keeps these controls out of raw buffer previews. |
| High | **A separate preview process protects scene state, while GPU and device resources are still shared.** The CLI owns startup and readiness. It can reset state before finishing, fail, or time out. Existing tests own instances with separate endpoints. [Scene application](../src/systems/CommandSystem.cpp) · [Startup deadline](../src/main.cpp) · [Owned renderer tests](../scripts/test_scene_recipe.py) | Show the primary and preview relationship and lifecycle. The preview starts windowed, has visible **Preview** identity, and offers Cancel, Focus, Close, and Retry as appropriate. Track the exact process. Never take over the primary OSC endpoint. Measure the primary render and device contention, including display placement on a fullscreen single-monitor setup. |
| High | **The previous packaging link is obsolete in this worktree.** Shared source files are under `assets/`, runtime `data/` is staged, local clips and the Shadertoy cache have separate lifecycles, and current staging does not copy `examples/`. A clean install can therefore differ substantially from the checkout. [Asset layout](../README.md#shared-assets-and-local-media) · [macOS staging](../scripts/stage_assets.py) · [Linux staging](../scripts/build_linux_minimal.py) | Use curated catalogs and package each example with its dependencies. Resolve Asset commands against the staged runtime paths for the supported build. Show unavailable entries for missing files or features. Keep catalog fixtures independent of personal media and caches. |
| High | **“Copy OSC command” needs a concrete representation.** The same fragment can go through texture or shader paths. Shader defaults, paired stages, primitive arguments, and string quoting can change whether a command actually works. The runtime can unload a texture before its new source succeeds. [Texture source load](../src/Texture.cpp) · [Shader stage lookup](../src/shader/Shader.cpp) · [SuperCollider serialization](../scripts/scene_recipe.py) | Show the use, typed target, source, and any required arguments. Mock a labeled SuperCollider snippet for an already-connected sender. Catalog entries with additional setup should show their requirements before any copy action is offered. Test actual clipboard text and parser/resolver parity before offering direct application. |
| Medium | **Texture-array slices are conditional.** The current flag is `ALLOW_TEX_2D_ARRAY=0`, and the depth helper returns zero in that configuration. Camera history uses a separate delayed-frame path. An Inspector preview can show the output after a pass or looper. [Array setting](../src/Config.h) · [Depth helper](../src/utils.h) · [Texture output and history](../src/Texture.cpp) | Mock the normal 2D and buffer cases first. Treat array controls as a capability-specific variant. Label the preview as the resource output. Resolve delayed-frame or per-pass inspection separately if needed. |
| Medium | **Several legacy paths need verification rather than visual preservation.** Layer thumbnails and hit targets are built with separate translations and positions. The default texture contributes to the thumbnail list before named textures and buffers are matched by position. Shader Inspector only consumes Back clicks, and the renderer switch does not forward the nested Escape and `q` handlers. [Thumbnail construction](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/Inspector.cpp) · [Hit targets](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/Inspector.cpp) · [Shader clicks](https://github.com/kasparsj/vosc/blob/6b381d0b5e1c4f26424ad5737a97f1c9b7d30b0e/src/inspector/ShaderInspector.cpp) · [Key dispatch](../src/systems/RenderSystem.cpp) | Preserve intended resource access. Use the resource shown in a row as the resource opened by that row. Test multiple named textures and buffers in the presence and absence of a default texture. Make **Back** a visible functional action and keep overlay-wide Escape separate. |
| Medium | **Overview’s facts need precise labels.** Startup can set a window title and discard the startup file object. Legacy scene reset can replace layers and shared resources. Scene snapshot dimensions come from window APIs, while PNG capture measures GL viewport pixels. [Startup title](../src/ofApp.cpp) · [Scene reset](../src/systems/CommandSystem.cpp) · [Snapshot and capture](../src/control/EngineControl.cpp) | Show an unnamed scene when provenance is unknown. Label render pixels and observed FPS explicitly. Include camera disabled and enabled states. Keep optional telemetry out of the default reading and avoid representing OSC as a connected session based on the current evidence. |
| Medium | **Console retention and attribution are bounded.** The log is a 512-entry ring-like history with elapsed time, sequence, severity, module, and bounded message text. Generic entries carry no structured layer identity. Clear currently empties shared storage, including diagnostics used by the control API. [Log storage](../src/Logger.cpp) · [Current Clear](../src/Logger.cpp) · [API diagnostic fields](../src/control/EngineControl.cpp) | Give Overview and Console the same local clear boundary. Preserve engine diagnostics independently. Show empty, filtered-empty, expired selection, unattributed error, and copy failure states. Open the exact sequence when it is retained and show a resource jump only when attribution is established. |
| Medium | **An example preview is often only the starting frame.** SuperCollider companions can provide later cues or audio input, and their default OSC port can point at the primary. Video needs a local readable MOV/MP4, camera uses the device and permission path, and HTML is compiled out of the default configuration. [Example requirements](../examples/README.md) · [Companion connection code](../scripts/generate_example_scd.py) · [Supported inputs](../src/scene/SceneFile.cpp) · [Camera permission](https://developer.apple.com/documentation/avfoundation/requesting-authorization-to-capture-and-save-media) | Tell the operator what the preview will show and what needs external setup. Provide file picker, cancelled selection, permission or device error, and unsupported build examples. Present the actual preview endpoint for any manual Attach workflow. |
| Medium | **The glass prototype and native rendering have different constraints.** The project targets macOS 12.6, uses OpenGL, and omits ImGui in the Linux minimal build. Uniform inspection currently queries GL values, and backdrop sampling or previews can add render cost. [Supported macOS baseline](../README.md#building-with-xcode-on-macos) · [Build flags](../src/Config.h) · [GL uniform reads](../src/shader/Shader.cpp) | Specify the visual result independently of Apple framework availability. Mock bright, compact, high-contrast, reduced-transparency, and reduced-motion states. Check scaling and render cost at native sizes before committing to a toolkit or changing the supported platform baseline. |

## Decisions to confirm in mockup review

- Choose the discoverable opener and keyboard shortcut. Keep normal focus navigation available inside the overlay and give input fields priority over renderer shortcuts.
- Confirm layer display labels and number shortcuts. The mockup default is the zero-based OSC identifier.
- Confirm one owned example preview at a time and its screen placement when the primary is fullscreen. Show how it closes and how the operator gets back to the primary window.
- Confirm the SuperCollider clipboard format and what initial bundled assets and scenes belong in the catalog. Choose the first supported desktop profile independently of other render profiles.

## Possible improvements after the core views

- **Read-only layer visibility and alpha.** The running renderer already reports both. They can explain an invisible layer next to its resource list. Test whether either deserves a default row before adding more controls. [Layer snapshot](../src/control/EngineControl.cpp)
- **A small onset-queue indicator.** The engine already exposes onset-gate state and the count of queued legacy commands. Consider a disclosed status if users need to distinguish waiting for onset from a failing render. [Runtime snapshot](../src/control/EngineControl.cpp)
- **Texture history and pass selection.** The current backing texture can depend on frame history, passes, or a looper. A future viewer could distinguish these outputs explicitly after the basic preview and resource identity are verified. [Texture output selection](../src/Texture.cpp)

## Verification boundary

Source review covered the app input and draw paths, Inspector and Console, scene and asset loaders, and packaging. Four macOS build/staging unit tests passed. The minimal Linux fixture passed SDK selection, Make dry-run, and fixture staging. These checks establish the staging behavior inspected here. Live resource identities, input routing, clipboard writes, preview ownership and performance on a working native scene remain acceptance work. The audit changed documentation only.
