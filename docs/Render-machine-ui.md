# Render-machine UI views

Draft for mockup review · 2026-11-22. [Design contract](../DESIGN.md) · [Codebase audit and mockup inventory](Render-machine-ui-audit.md)

The floating dock has four destinations: **Overview**, **Inspector**, **Console**, and **Browse**. Details open above the dock. **Back** returns to the originating item with its selection and scroll position. **Escape** returns directly to clean output. The scene continues rendering. V1 preserves the current Inspector's capabilities and adds two catalogs inside Browse.

The current behavior below comes from the source. The earlier macOS smoke check covered Inspector and Console visibility. Resource navigation and texture mutations still need runtime verification on a working scene.

## Output and Overview

| View | First-version behavior |
| --- | --- |
| Output | The composition fills the window. A deliberate local action opens the dock. Keep a discoverable entry outside the clean render, with the exact desktop entry and shortcut confirmed in review. Capture excludes all operator UI. Errors remain available within the log's retention window and leave clean output visually undisturbed. |
| Overview | Show the scene name only while its identity is known. Use an unnamed state for ordinary OSC sessions and after a replacement with no known title. Label composed output size in pixels and observed FPS separately. Disclose camera position when enabled. Show the newest retained error since Clear view and open its exact entry while available. Console search does not affect the summary. Offer a resource jump only with verified attribution. |

The current debug overlay displays frame rate and, when enabled, camera position after composition. The app can use the startup scene title as the window title. [Debug draw order](../src/systems/RenderSystem.cpp#L210) · [Startup window title](../src/ofApp.cpp#L23) · [Capture behavior](Engine-api.md)

The new UI reads the local renderer directly. The optional control socket is a separate client interface. It exposes window width and height in the scene snapshot, while composed PNG capture measures backing pixels. The mockup uses composed output dimensions and a distinct unavailable state if they cannot be measured. [Scene snapshot](../src/control/EngineControl.cpp#L1655) · [Capture dimensions](../src/control/EngineControl.cpp#L1664)

## Inspector views

| View | Current capability to retain | Proposed presentation |
| --- | --- | --- |
| **Globals** | Wireframe geometry from the scene layers, named global texture thumbnails, pooled shader names and paths, and OSC input amplitude with a numeric reading, a circle, and history trace. Global texture and shader entries open their inspectors. [Globals and previews](../src/inspector/Inspector.cpp#L45) · [Inputs](../src/inspector/Inspector.cpp#L230) · [Global selection](../src/inspector/Inspector.cpp#L290) | A compact scope selector for **Globals** and **Layers**. Reveal **Geometry**, **Textures**, **Shaders**, and **Inputs** within Globals. Label the input with its existing registry name and keep the amplitude graph with its value. Associate wireframes with their source layers. |
| **Layer** | A selected layer's geometry wireframe, default texture, shader status or path, bound shader texture thumbnails, and buffer thumbnails. The layer view has drill-down paths for the shader, default texture, named textures, and buffer textures. [Layer contents](../src/inspector/Inspector.cpp#L70) · [Layer selection paths](../src/inspector/Inspector.cpp#L331) | A scrollable list of all current layers opens the selected layer's resources. Show stable identifiers that match OSC selectors. Keep the layer name or index visible in each resource detail. |
| **Shader** | Name, path or load status, standard-versus-Shadertoy classification, reflected uniforms and their GL types and available values, VOSC variables, named textures, and buffer thumbnails. The current detail shows the thumbnails without drill-down actions on those thumbnails. [Shader detail](../src/inspector/ShaderInspector.cpp#L92) · [Shader clicks](../src/inspector/ShaderInspector.cpp#L240) | Lead with shader identity and current load state. Use separate **Uniforms**, **Variables**, and **Bindings** sections. Show bound texture and buffer previews as links into the corresponding resource. Scroll long lists to the end. Show when a reflected or live value is unavailable. |
| **Texture** | Name, width and height, depth where available, GL internal format and target, horizontal and vertical wrap, minification and magnification filters, and a fitted preview. A full VOSC texture object also exposes its variables, ordered shader-pass names, its shader when present, and two live update flags. [Metadata and flags](../src/inspector/TextureInspector.cpp#L95) · [Passes and preview](../src/inspector/TextureInspector.cpp#L179) · [Texture variable list](../src/inspector/TextureInspector.cpp#L76) | Put the live preview and dimensions first. Disclose sampling metadata, passes, and variables on demand. The shader link returns to the originating texture on **Back**. Put scene-changing flags in a clearly labeled **Texture updates** section on the owning texture. |
| **Buffer texture** | The Inspector opens the texture representation of a shader buffer through the texture detail path. It receives a raw texture pointer, so the available surface is texture metadata and preview. [Buffer path](../src/inspector/Inspector.cpp#L377) · [Raw texture binding](../src/inspector/TextureInspector.cpp#L24) | Show **Buffer** and its binding name in the path. Reuse texture preview and metadata. Offer object-level actions only on resources that support them. |
| **Enlarged preview** | Enlarge a texture or buffer with aspect ratio preserved. The source includes click-to-cycle support for texture-array slices, and the checked-in configuration disables the depth path. [Enlarged view](../src/inspector/TextureInspector.cpp#L245) · [Slice cycling](../src/inspector/TextureInspector.cpp#L357) · [Build flag](../src/Config.h#L21) | Open a larger view on demand. On a verified array-capable build, show the current slice and explicit previous, next, and direct slice controls. In the ordinary 2D flow the preview has no slice controls. **Back** returns to the resource and **Escape** clears the overlay. |

**Uniforms and variables.** Uniform values come from the currently linked GL program for supported types. The variables view displays the engine's configured values, including scalar and numeric arrays, vectors, and colors where supported. Keep those two concepts visible as separate sections. The current uniform and variable draw paths truncate long lists. [Uniform reflection and values](../src/shader/Shader.cpp#L1424) · [Variable display](../src/inspector/VarsInspector.cpp#L14)

**Texture updates.** Preserve the ability to set and clear both `isStatic` and `needsUpdate`. A static texture skips ordinary updates unless one is requested. The engine consumes a pending update and clears the flag on an eligible update. Show the pending state accurately and label these controls as changes to the running texture. Restrict them to the supported owning object. [Flag actions](../src/inspector/TextureInspector.cpp#L323) · [Update behavior](../src/Texture.cpp#L187)

**Resource identity.** Keep the visible source scope and binding name with the item. When a live command replaces or removes the selected resource, show **Resource changed** or **Resource unavailable** and return to the surviving parent. Revalidate a live texture action against the intended owning object before dispatch. Surface shared scope when an action affects a shared texture. A matching layer index after a scene reset is insufficient to restore a selection or authorize an action on that layer.

**Preview identity.** Label the rendered texture output separately from the named source and ordered pass list. The existing preview can show the last pass, a loop output, or a history frame. Present the available output even when there is no independently selectable source image. Use distinct states for an unloaded resource, an unsupported preview, and a valid black image. [Texture output selection](../src/Texture.cpp#L449)

## Console

The existing Console draws a bounded, severity-colored log with scrolling, Copy, and Clear. The logger records message text, module, severity, elapsed time, and sequence. The current draw code checks a text filter internally and exposes no editable filter field. Current Clear empties the shared in-memory log. [Console UI](../src/Logger.cpp#L80) · [Retained fields and limits](../src/Logger.cpp#L12) · [Diagnostics API mapping](../src/control/EngineControl.cpp#L1440)

Keep chronological messages, copy, clear, and the ability to read older entries while new ones arrive. Show severity in text, plus elapsed time and source where available. Follow the latest messages while the operator is at the end. When they scroll back, hold their reading position and offer **Jump to latest**. **Clear view** starts the local Console and its Overview summary from the present point while retaining the bounded diagnostic stream used by other engine consumers. It clears the local row selection. **Copy entry** copies the selected message. **Copy filtered log** copies all retained rows matching the active filter and local clear boundary, including rows outside the viewport. Offer an **Errors** filter covering error and fatal severity and a text filter. Show distinct states for an empty log, no matches, and an entry that aged out. A jump from Overview reveals the exact entry even when the current filter would hide it, with a visible indication if the filter changed.

## Browse

Open **Examples** or **Assets** inside Browse. Both use the same pattern: search by name, narrow by category, select an item, and open its details. Keep selection, filter, and scroll position when returning from details or switching between catalogs. Show a saved thumbnail where one exists and a type-labeled placeholder otherwise. Browsing and selecting leave the running scene alone.

### Examples

An example is a complete runnable scene. Use the existing example manifests and index as the source of truth for scene files and setup. A small catalog supplies display metadata such as category, what the example demonstrates, preview, requirements, and companion links. Keep each manifest with its assets when packaging it. Resolve catalog paths in development and in the installed build. The current staging script copies renderer assets and does not package the Examples tree. [Examples index](../examples/README.md) · [Native scene format](Native-scene-v2.md) · [Current staging inputs](../scripts/stage_assets.py#L17)

- **Details.** Show what plays immediately and which behaviours require later SuperCollider cues or live input. Offer **Reveal scene file** and access to companion files and instructions where present. A preview launch does not evaluate companion code. If a companion can attach to the preview, show the preview's actual endpoint and the relevant Attach instructions. Some existing scripts have a default port and a Setup block that resets a renderer. [Companion instructions](../examples/README.md#running-the-scene-companions) · [Generated Attach and Setup](../scripts/generate_example_scd.py#L112)
- **Requirements.** Show unsupported capabilities and missing inputs before launch where possible. Offer **Choose clip** for a readable local MOV or MP4 and a camera selector for camera examples. Show clear recovery for cancelled selection, unreadable or unsupported media, camera unavailable or denied, and timeout. Start the renderer's permission path only after an explicit launch. An HTML example should show its destination and network/build requirement before launch. [Input validation](../src/scene/SceneFile.cpp#L173) · [Camera startup](../src/tex/WebcamTex.cpp#L23)
- **Launch.** **Open in Preview Window** starts a separate windowed renderer through the existing `--scene` path. Give it a clear **Preview** identity, its own OSC listener, and a private control endpoint if needed. Keep the parent responsive. Show **Starting** with **Cancel**, **Ready** with **Focus Preview** and **Close Preview**, and **Failed** with **Retry** and launch details. **Ready** means `VOSC_SCENE_READY` from the owned process after composition. If that process then exits, show the closed or stopped state. Close and cancel affect only that instance. Launch leaves the primary's scene, OSC listener, and fullscreen state intact. GPU and device contention still need measurement. [Startup timeout](../src/main.cpp#L79) · [Readiness](../src/ofApp.cpp#L39) · [Existing test harness for isolated renderers](../scripts/test_scene_recipe.py#L226)
- **Mockup default for review.** Show one active preview at a time so the operator can identify and stop it. While it is open, return to it or close it before launching another. Test the behaviour on a single monitor and with dedicated output. The preview should be distinguishable from the live window even when both show the same scene.

### Assets

An asset is a reusable source. Start with a curated local catalog of supported shaders, textures, models, and built-in sources. Store each entry's stable ID, display name, kind, source reference, preview if available, origin, and requirements. A shader entry represents the usable entry point with any required companion stages or includes. A model entry carries its linked files. Keep the catalog entries and the files they depend on together in packaged builds. Show attribution where known. Author shared assets in `assets/` and resolve commands against the installed renderer's staged `data/` tree. Scene-local example assets, local clips, caches, and renderer support files have separate purposes. [Shared assets and local media](../README.md#shared-assets-and-local-media) · [Staging](../scripts/stage_assets.py#L17) · [Shader path resolution](../src/shader/Shader.cpp#L348)

- **Details.** Show the asset's type, preview, source and requirements. Distinguish a shader used as a texture source from a shader applied to a layer program. These are separate uses with different commands.
- **Target.** Choose a current layer by its OSC identifier. Keep that choice visible. Require a new selection if the target disappears or a replacement scene reuses the same index. Show the empty layer list and what to do next when no target exists.
- **Use.** Show the OSC address, typed arguments, use, and target before copying. Generate the correct source form for that use. Texture sources use `/tex`, layer programs use `/shader`, and model or primitive sources use `/geom`. Use source references resolvable by this renderer. Mark sources requiring extra setup as such and offer a command only when it represents a valid supported use. Show copy success or failure. Copy never sends a message. [Texture commands](Texture-commands.md) · [Shader commands](Shader-commands.md) · [Geometry commands](Geometry-commands.md)
- **Mockup default for review.** Label the copied text as a SuperCollider snippet for an already connected `~visuals` client, with a separate human-readable address/arguments preview. Confirm this format before implementation. The repository already serializes SuperCollider string and float arguments for scene companions. [Serialization](../scripts/scene_recipe.py#L30) · [Example usage](../scripts/generate_example_scd.py#L99)

Keep direct asset application and replacing the current scene for a later decision about live-state replacement and failure handling. Use the Browse catalog and explicit copy or preview action for v1. [Current scene reset during startup](../src/systems/CommandSystem.cpp#L826)

## Recommended first-version improvements

1. **Make every existing resource reachable.** Use one scrollable Inspector scoped to Globals or a layer. Keep the origin visible in resource detail, add **Back**, preserve arrow-key and pointer access, and handle a layer or resource disappearing during scene changes. Keep passive navigation from changing scene state or interrupting an active shader trial. Current key and pointer handlers notify or interrupt trials before routing many actions. [Input routing](../src/VOSC.cpp#L121) · [Layer replacement](../src/systems/RenderSystem.cpp#L460) · [Blender Outliner reference](https://docs.blender.org/manual/en/4.4/editors/outliner/interface.html)
2. **Connect the error to the investigation.** Open the Console from Overview with the matching entry selected when available. Offer a resource jump only when identity is reliable. Provide severity and text filters and copy actions. The generic logger fields alone do not establish layer or resource identity. [Logger record](../src/Logger.h#L11) · [VS Code debugger reference](https://code.visualstudio.com/docs/debugtest/debugging)
3. **Make previews and long readouts practical.** Open shader bindings directly, scroll complete uniform and variable lists, and give array slices explicit navigation. Start with the live previews and metadata already exposed by VOSC. [Xcode bound resources](https://developer.apple.com/documentation/xcode/inspecting-the-bound-resources-for-a-command) · [Xcode texture slice previews](https://developer.apple.com/documentation/xcode/inspecting-live-resources-at-runtime)

Keep GPU frame capture, per-pixel debugging, uniform editing, and a performance timeline for a later scope review. The current FPS reading covers the first-version Overview. Optional GPU timing has a narrower measurement scope and should have its own labeling and validation if exposed later. [VOSC performance telemetry](Performance-telemetry.md) · [Xcode GPU debugging reference](https://developer.apple.com/documentation/xcode/metal-developer-workflows)

### Shortcut and behavior review

- Today `f` toggles fullscreen, `Tab` toggles debug, and `c` toggles the Console. The renderer routes number keys to Inspector selection when debug is visible and to blend modes when hidden. Inspector `0` selects Globals and `1–9` pick layer array positions when its root view has focus. The shader and texture classes contain some Escape and `q` handling, and the inspected renderer key switch forwards only numbers into the Inspector. Treat visible **Back** and overlay-wide Escape as deliberate improvements. [App shortcuts](../src/ofApp.cpp#L90) · [Window shortcuts](../src/VOSC.cpp#L133) · [Renderer dispatch](../src/systems/RenderSystem.cpp#L488) · [Inspector key handling](../src/inspector/Inspector.cpp#L414)
- Texture reload, layer reset, wireframe changes, fullscreen, and output-mode blend shortcuts remain renderer commands. Decide the exact overlay opening and view-shortcut map during review. Input consumed by the overlay acts only on the focused UI. Texture-update commands are the deliberate live changes inside Inspector.
- Confirm the display convention for layers. The current Inspector calls the first slot **Layer 1** while OSC integer selectors index layers starting at zero. The draft favors matching OSC identifiers and documenting the numeric key mapping. [Current label](../src/inspector/Inspector.cpp#L70) · [OSC target selectors](Home.md#target-selector-model)

**Mockup keyboard model.** Opening focuses the current dock destination. Left and Right move between destinations when the dock has focus. Tab and Shift-Tab move between controls. Up and Down move through lists when a list owns focus. Enter or Space activates the focused action as appropriate. Opening a detail puts focus on its first meaningful control. Back returns focus to the originating item when it still exists. Escape in the overlay returns to clean output. A native file picker handles its own Cancel or Escape and returns focus to its opener. Typing and navigating a filter field stay within the field. Show keyboard focus separately from active selection and give icon-only controls accessible names. [Apple keyboard guidance](https://developer.apple.com/design/human-interface-guidelines/keyboards/)

## First-version review criteria

| Workflow | Mockup review | Native verification |
| --- | --- | --- |
| Open and dismiss diagnostics | Reveal the dock, navigate by pointer and keyboard, and return to clean output with Escape. Check a compact window and a bright scene. | Verify that the render continues, the window mode stays the same, and captured preview pixels exclude the overlay. |
| Browse Globals and Layers | Show populated scopes with wireframes, named resources, and input history. Open a resource, go back, and recover when a selected resource disappears. | Verify inputs and previews against a working scene. Check multiple named resources with and without a default texture, including hit targets and selection after a live scene change. |
| Inspect a shader or binding | Follow a shader binding to its texture or buffer. Scroll past the initially visible uniforms and variables. Back restores the originating row and scroll position. | Verify linked shader values and configured variables, and confirm that each binding opens the correct resource. |
| Inspect or update a texture | Enlarge a 2D texture and return to detail. Treat the array slice chooser as a capability variant. Show update controls only on a resource that supports them. | Verify normal and raw buffer previews, and setting and clearing both texture-update flags. Verify slices on an array-capable build if one enters scope. Verify passive inspection leaves an active trial running and that a stale action can never change the replacement resource. |
| Find and copy an error | Open the matching Console entry from Overview. Show a resource jump when identity is known. Exercise error filtering, copy, and return to output. | Verify entry selection, real clipboard contents, retention when new messages arrive, and how Clear view interacts with other diagnostic consumers. |
| Preview an example | Find a scene and open it in a distinct preview window. Show input selection, starting and cancellation, ready and closed, and unsupported or failed recovery. | From an installed build, verify that a packaged example reaches its first composed frame. Check owned-process cleanup, GPU/device contention, and that success, failure, and close leave the primary window and its OSC state intact. |
| Find and use an asset | Filter by kind, choose an asset and target layer, review the use and command, and copy it. Show no targets, an unavailable asset, a replaced target, and copy failure. | Check that packaged source files resolve and the actual clipboard contains the correct typed target and source for texture, shader, and geometry entries. Exercise a multi-stage shader entry and escaping. Verify that Copy leaves the current scene unchanged. |

The current layer thumbnails and hit testing use separate offsets and positional indices. Use an example with several named texture and buffer bindings for the native hit-target check. [Layer thumbnail rendering](../src/inspector/Inspector.cpp#L171) · [Input hit testing](../src/inspector/Inspector.cpp#L345)
